# @girs 精简类型声明快照

本目录随仓库分发 [gjsify](https://github.com/gjsify) 生成的 TypeScript 类型声明，
供原生 `tsc` 严格编译扩展、真实 GJS 契约与编辑器使用。项目工具链不引入 Node/npm，
因此不通过 `node_modules` 安装，而是把入口实际引用的 `.d.ts` 收录为快照；
`tsconfig.json` 用 `paths` 把 `@girs/*` 映射到本目录。

## 收录范围

只收录当前源码入口实际引用的 32 个 `.d.ts`：扩展基类（`resource://` 模块声明与
`Extension` 类）、GJS 全局、Gio/GLib/GObject/GModule/Cairo。为控制体积，**没有**收录
`@girs/gnome-shell/extensions/global`（`Shell.Global`、`Meta`、`Clutter`、`St` 等完整
闭包约 11 MB），也**没有**收录 `prefs`、Adw/GTK 相关类型。

因此 `global` 与焦点窗口接口仍由 [../GJS环境.d.ts](../GJS环境.d.ts) 保留约 30 行本地
最小声明；其余运行时类型全部来自官方声明，不再手写。

## 与上游的差异

只做以下机械调整，声明内容不改写：

- 删除入口闭包之外的 `.js`/`.cjs` 与未引用的 `.d.ts`（例如 Gio 的 `-vocabulary`）；
- `@girs/gnome-shell` 的 `dist/` 扁平化为包根（`extensions/`、`types/`）；
- `dist/types/extension-metadata.ts` 改名为 `extension-metadata.d.ts`，内容不变。

修改本目录时只删除或改名，不手工编辑生成文件；需要更多类型面时优先重新收敛入口。

## 升级方法

1. 从 [来源.json](来源.json) 对应包的 tarball 地址下载新版本，校验 `sha512`；
2. 在 `builddir/临时/` 下解压出 `node_modules/@girs` 结构，用 `tsc --listFiles` 收集
   入口闭包（入口为 `@girs/gjs`、`@girs/gio-2.0/ambient`、`@girs/glib-2.0/ambient`、
   `@girs/gnome-shell/extensions/extension/ambient`；`gjs` 与 `gnome-shell` 包会带入
   `gobject`、`gmodule`、`cairo`）；
3. 按上节规则替换文件，更新 [来源.json](来源.json)、本文件与
   [第三方许可证](../../文档/04-第三方许可证.md)；
4. 运行 `tsc -p tsconfig.json --noEmit` 与 `cargo 检查`。

版本升级只由维护者手工执行，不与工具链最新版自动联动；扩展声明支持
GNOME Shell 45–52，而这里的类型基准为 51.0.1，本仓库实际只用 GNOME 45+ 已有的稳定 API。
