# 使用指南

返回 [文档索引](README.md)。配置字段见 [配置说明](07-配置说明.md)，完整按键见 [行为清单](03-行为清单.md)。

## 运行前提

- 支持 GNOME Wayland。X11 不受支持；程序只预检 GNOME 桌面，不检测或拦截 X11。
- 当前会话须具备 input 组权限，并能写入 `/dev/uinput`。可用 `id -nG` 和
  `ls -l /dev/uinput` 检查；权限缺失时由管理员按发行版方式配置，Mackey 不自动提权或安装规则。
- 使用 systemd 用户服务、GSettings 和 GNOME 扩展。扩展声明的 Shell 版本见
  [metadata.json](../扩展/mackey-focus@kotonex/metadata.json)。
- 二进制包支持 x86_64/aarch64，使用构建环境的 glibc，不保证兼容所有旧版发行版。

## 安装与首次启用

从 [发行页](https://github.com/KOTONEX/Mackey/releases/latest) 下载对应架构的二进制包，
核对 `SHA256SUMS-<版本>.txt` 后解压，在包目录执行：

```bash
./mackey 安装
```

源码用户先按 [贡献指南](../CONTRIBUTING.md) 准备工具，再执行 `cargo 运行 安装`。
两种入口执行相同安装逻辑。安装默认请求 xremap 的 `gnome` 特性，缺少该发行资产时可回退 `full`；
已有自定义引擎时可加 `--不下载`。如果下载失败，安装会继续部署其他文件，启用前仍须取得可用引擎。

安装保留用户已有字段、补齐缺字段；损坏的 JSON 会先备份为 `config.json.bak-*`。
默认先停用现有 Mackey 服务，再重写二进制、扩展和用户单元；`--保持运行` 可保留旧进程，
但磁盘文件更新不表示运行中的二进制或扩展已经重新加载。

首次安装后重新登录，使新扩展和新增的组权限进入会话，再执行：

```bash
mackey 体检
mackey 应用
mackey 状态
```

`应用` 会生成配置，确认并备份实际冲突的 GNOME 键位、迁移它们，最后重启服务。
默认入口是 `${XDG_BIN_HOME:-~/.local/bin}/mackey`；目录未加入 PATH 时使用完整路径。
`状态` 中应确认 `mackey-focusd.service` 与 `mackey-engine.service` 均运行。
`体检` 用于检查权限、引擎、焦点来源和冲突；它不会主动启动服务，不能替代运行状态检查。

## 日常操作

| 命令 | 行为 |
| --- | --- |
| `mackey 状态` | 显示引擎位置、两项服务和扩展状态 |
| `mackey 体检` | 检查环境；发现待处理问题返回失败 |
| `mackey 日志 50` | 查看焦点桥及引擎的最近日志 |
| `mackey 探测` | 只读探测 GNOME 键位与迁移计划 |
| `mackey 生成` | 写出 xremap 配置、迁移计划和行为文档，不应用 GNOME 迁移或重启服务 |
| `mackey 应用` | 重新生成、备份并迁移冲突、重启服务；`--确认执行` 跳过交互确认 |
| `mackey 启用` | 启用并启动服务，先验证焦点来源和套接字 |
| `mackey 停用` | 停用两项服务；GNOME 键位迁移仍保留 |
| `mackey 还原` | 按备份还原 GNOME 键位；成功后删除已恢复备份，不负责停服务 |
| `mackey 版本` | 显示项目版本与引擎路径；`--version` 只显示项目版本 |

完整参数用 `mackey --help` 或 `mackey <子命令> --help` 查看。
修改配置后运行 `mackey 应用`；仅想关闭重映射时用 `mackey 停用`。
如需同时还原 GNOME 键位，先停用，再运行 `mackey 还原`。

## 升级与镜像更新

升级 Mackey 时，用新二进制重新运行 `安装`，按需要重新登录加载扩展，然后执行 `体检`、`应用` 和 `状态`。
从不兼容的旧 Python 版更新，先按 [旧版重装步骤](07-配置说明.md#旧版重装) 还原并清除旧配置。

保留 HOME 的系统镜像更新不会删除用户安装。已启用的焦点桥在登录期间等待扩展来源，
失败每两秒重试；来源与套接字就绪后才拉起引擎。桥接故障时引擎随之停止，桥接恢复后重新拉起。
主动执行过 `停用` 时服务会保持关闭，需手动 `启用` 或 `应用`。

## 卸载

```bash
mackey 卸载 --预演
mackey 卸载
```

卸载默认停用服务、还原 GNOME 键位，删除本项目的扩展、二进制、配置、缓存和状态。
`--保留配置` 保留配置目录，其中包括用户配置和生成配置；缓存、状态及程序文件仍会清理。
`--确认执行` 跳过交互确认。还原失败时保留配置与备份，并报告失败，不继续当作成功卸载。

## 故障排查

| 现象 | 检查与处理 |
| --- | --- |
| 安装后按键没有变化 | 先看 `状态`，安装本身不启动；扩展加载、权限生效后执行 `应用` |
| 扩展未加载或焦点来源不可用 | 新装扩展或更新元数据后重新登录；结合 `日志` 检查 GNOME 来源，不强制重启当前桌面会话 |
| 服务找不到输入设备 | 检查当前会话 input 组及设备权限；新增组权限后重新登录 |
| 体检通过但没有重映射 | `体检` 不保证服务运行，单独检查两项服务，并确认设备过滤覆盖当前键盘 |
| 终端里 ⌘C 变成 Ctrl+C | 停用重映射，检查实际加载的版本、焦点来源及终端应用匹配；当前实现会在焦点查询失败时退出桥接并联停引擎 |
| 镜像更新后无效 | 查 `状态` 与两项服务日志，区分主动停用、权限变化和来源重试；不要先假定安装被删除 |
| 个别应用未识别合成按键 | 可尝试调整 `keypress_delay_ms`；应用匹配和配置档见配置说明 |

出现其他引擎同时抓取键盘时，先识别其来源，避免多个全局重映射引擎并行。
当前安全边界及焦点保护机制见 [架构与边界](02-架构与边界.md)。
