# main 与 rust：结构、用法、代码量和性能

2026-10-08 实测。基线为 Python 版 `main` 的 `69b000f`（1.3.0），
结构与用法对应当前 Rust 分支；代码量与性能为保存的测量快照。本次实测采用 Edition 2024。
本文数据对应分支源码的 release 构建，发布附件应以对应标签的源码为准。

## 项目结构

| 项目 | main | rust |
|---|---|---|
| 用户入口 | Bash `bin/mackey`，由脚本编排各工具 | 原生 `mackey`，`命令/mackey` 仅启动已构建程序 |
| 主要逻辑 | Python 生成器、焦点桥、下载器、键盘识别 + Bash 安装/服务管理 | `源码/库/` 中 12 个功能模块与 1 个库入口，统一配置、服务、下载、焦点、开发与打包逻辑 |
| GNOME 扩展 | JavaScript，通过 D-Bus 暴露焦点 | TypeScript 源码，编译为 GNOME 使用的 JavaScript，协议一致 |
| 运行环境 | Bash、Python，焦点桥使用 PyGObject/GI 或 busctl | 原生可执行文件与系统 glibc；无需 Python/GI 运行时 |
| 实际按键映射 | 外部 xremap | 仍由外部 xremap 执行 |
| 安装产物 | 依赖仓库中的工具/资源 | 可执行文件内嵌清单与扩展，安装后独立运行 |
| 开发与发布 | 多个 Make/Shell 入口、手工版本文件 | Cargo 唯一版本源，原生检查/打包，Git 生成日志，双架构工作流 |

两版均保留 GNOME 键位备份、冲突迁移与卸载还原。新版用 HOME 路径保护、原子写入、下载
大小/ELF 架构校验、IPC 限额与独立的真实扩展契约测试覆盖这些边界。

## 用法

| 操作 | main | rust |
|---|---|---|
| 安装 | `./install.sh` | 源码先 `cargo build --locked --release --bin mackey`，再 `./安装.sh`；二进制包运行 `./mackey 安装` |
| 健康检查 | `mackey doctor` | `mackey 体检` |
| 生成 | `mackey generate --no-probe` | `mackey 生成 --不探测` |
| 应用 | `mackey apply` | `mackey 应用` |
| 还原 | `mackey revert` | `mackey 还原` |
| 卸载 | `./uninstall.sh --yes` | `./卸载.sh --确认执行` |
| 自有配置 | `modifier_layout`、`engine`；`apple`/`pc-swap`/`auto` | `修饰键布局`、`引擎`；`苹果`/`微软`/`自动` |
| 开发验收 | 多个 Make 目标 | `cargo 检查` |

新版不读取旧别名、字段或布局值；更新时先运行旧版卸载脚本，再安装新版。
[xremap 外部字段与重新安装步骤](07-中文接口迁移.md)另有说明。

## 代码量

以下代码量与性能为已保存的测量快照；后续安装、测试与发布编排的 Rust 迁入不包含在该快照中。

用 tokei 统计 Git 快照中的实际代码行，不包含注释、空行、JSON/YAML/TOML、Markdown、
Cargo.lock、许可文本或构建产物；包含测试和类型声明。

| 语言 | main | rust |
|---|---:|---:|
| Bash/Shell | 1,342 | 629 |
| Python | 2,303 | 0 |
| Rust | 0 | 3,675 |
| JavaScript | 173 | 201 |
| TypeScript | 69 | 81 |
| Makefile | 112 | 0 |
| 合计 | **3,999** | **4,586** |

总量增加 **587 行（14.7%）**。Rust 将类型、边界校验、打包和部分测试显式写入代码；
这里包含了这些新增职责，不能把行数差直接解释为某种语言本身更复杂。
运行时减少脚本解释器依赖，源代码总体并未缩短。x86_64 原生可执行文件约 11.4 MB。

## 测量方法

主机为 Intel Core Ultra 7 255H（16 个逻辑 CPU）、x86_64 Linux 7.2.8-ogc2，
Python 3.14.7、rustc 1.99.0；Rust 使用带锁文件的宿主 `release` 构建。

- 使用相互独立的 Git 快照与临时 HOME/XDG，未读取或修改实际用户配置。
- 帮助命令每版 120 次，完整生成每版 80 次；各预热 10 次，随机交替运行。
  生成包含完整进程启动、115 条映射、文档与文件落盘，Rust 的原子写入和 fsync 保留。
- 生成器双方分别使用等价的苹果布局配置，关闭 GNOME 探测；逐值比较 `xremap.json`
  与 `relocations.json`，结果一致。
- 焦点测试在独立 D-Bus 会话运行真实扩展代码，仅替换 GNOME Shell 基类与窗口对象，
  双方查询同一个窗口类名/标题。每版每模式 3 轮，每轮预热 50 次后测 1,500 次，
  每次重新连接 Unix socket，并检查响应，共 4,500 个有效样本。
- 内存读取进程的 `/proc/<pid>/status`；短命令的 wait4 高水位不作为内存结论。
  未锁定 CPU、未清空磁盘缓存；这是当前主机预热后的实测，不代表冷启动或所有机器。

汇总数据保存在 [对比实测.json](对比实测.json)。毫秒越低越好，RSS 为驻留内存。

## 进程启动与完整生成

| 操作 | main 中位 / P95 | rust 中位 / P95 | 中位耗时比例 |
|---|---:|---:|---:|
| 帮助启动 | 7.165 / 8.036 ms | 1.039 / 1.279 ms | main 是 rust 的 6.89 倍 |
| 完整生成并写文件 | 60.782 / 64.727 ms | 7.994 / 9.555 ms | main 是 rust 的 7.60 倍 |

## 焦点桥

| 模式 | main 中位 / P95 | rust 中位 / P95 | main / rust 驻留内存 |
|---|---:|---:|---:|
| 固定焦点 | 0.169 / 0.243 ms | 0.064 / 0.128 ms | 33.08 / 5.68 MiB |
| D-Bus、缓存 40 ms | 0.155 / 0.273 ms | 0.078 / 0.164 ms | 33.46 / 7.32 MiB |
| D-Bus、禁用缓存 | 0.557 / 1.432 ms | 0.409 / 1.074 ms | 33.56 / 7.40 MiB |

默认缓存模式中，Rust 的中位查询耗时约为 main 的一半，驻留内存减少约 **78%**；
首次成功响应从 76.35 ms 降为 4.12 ms。顺序请求吞吐从约 6,161 提高到 12,047 次/秒，
这只是测试循环吞吐，不等同于实际按键速率。
禁用缓存时 Rust 有一次 **20.81 ms** 的长尾（main 最大 2.01 ms），不能宣称每个请求都更快。

## 验证边界

当前分支通过格式、Clippy、Rust/GJS 类型、ShellCheck、115 条旧版映射差分、Rust 单元与集成
测试、隔离安装/卸载、旧配置拒绝与原文保留、13 项 GJS/D-Bus 契约断言和发行包解压验证。

真实键盘端到端测试未运行：本机已有全局捕获键盘的 xremap，双引擎可能同时捕获测试设备。
上述数据测量的是管理命令和焦点桥；实际按键链路仍使用 xremap，不能据此推导真实输入延迟。
