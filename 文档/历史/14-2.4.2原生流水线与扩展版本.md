# 2.4.2 原生流水线与扩展版本

> 历史归档：保留当时的环境、结论及后续补记，不代表当前使用方式或本轮验证。当前入口见 [文档索引](../README.md)。

## Shell 迁移

仓库不再保留安装、卸载、源码入口脚本及编译器准备 composite action。
源码使用 `cargo 运行 安装`、`cargo 运行 卸载`；发行包使用 `./mackey 安装`、`./mackey 卸载`。

`.github/流水线.rs` 只依赖 Rust 标准库，可直接由 `rustc` 编译，负责 HOME 源码副本、
临时 runner 依赖、稳定 Rust 与微软官方原生 TypeScript 的准备。
原生编译器按最新正式发行的架构资产下载，校验官方 SHA-256、归档路径与文件类型、ELF 标记及可执行版本；
工具链准备不需要 Node/npm。平台提供的 `GITHUB_PATH` 与 `GITHUB_ENV` 命令文件只用于当前 CI 任务。

`源码/库/流水线.rs` 负责标签与 Cargo 版本一致性、主线归属判断、草稿附件上传及公开发布。
已公开发行拒绝覆盖；只有属于远程 `主线` 历史的提交可正式发布，其他标签为预发行且不设 Latest。
工作流 YAML 保留官方 Actions 和单行 Rust/Cargo 调用；命令仍由 GitHub 平台的默认启动器执行。

## 扩展管理器版本行

Extension Manager 0.6.5 在整数 `version` 缺失时会隐藏整行，即使已有 `version-name`。
[上游对应代码](https://github.com/mjakeman/extension-manager/blob/v0.6.5/src/exm-extension-row.c#L268)
以 `version != NULL` 决定版本行可见性，存在时优先显示 `version-name`。

`源码/扩展元数据.rs` 统一从 Cargo 项目版本生成两字段：

- `version-name`：完整项目版本，例如 `2.4.2`。
- `version`：`主版 × 1000000 + 次版 × 1000 + 补丁`，例如 `2004002`。

次版、补丁均小于 1000，整数必须处于正的 32 位范围；无效显示版本、溢出或无效 JSON 会使构建失败。
安装、发行包与扩展 ZIP 共用同一份生成元数据，不另设手工版本来源。
这个整数用于 GitHub 自分发包；若另向 extensions.gnome.org 发布，由网站管理其发布序号。

本机现有 2.4.1 仅补齐磁盘元数据中的 `version=2004001`，保留版本名、扩展脚本、配置和运行中的键盘服务。
原文已在 HOME 备份。GNOME 当前会话缓存仍需下次登录刷新；没有自动注销、重启 Shell 或停止服务。
