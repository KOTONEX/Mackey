# 构建与发行

返回 [文档索引](README.md)。本地环境和统一检查见 [贡献指南](../CONTRIBUTING.md)，
发布约束统一见 [项目规范](项目规范.md)。

## 原生构建

构建使用最新稳定 Rust/Cargo、C 编译器与原生 ELF TypeScript 编译器 `tsc`。
应用依赖提交 `Cargo.lock` 并使用 `--locked`；Edition 显式声明当前值，随稳定版迁移验收更新。
普通构建不联网更新工具链或修改全局环境。

```bash
cargo build --locked --bin mackey
cargo build --locked --release --bin mackey
cargo 运行 <子命令>
cargo 打包
```

前两个命令使用 Cargo 配置的目标目录，默认是 `target/debug/` 和 `target/release/`。
`cargo 打包` 显式构建 rustc 宿主目标，从 Cargo 元信息读取产物位置，不假定固定目标目录。
发行包写入 `builddir/发行/mackey-<版本>-linux-<架构>.tar.gz`，并实际解压执行校验。
源码命令由 Cargo 构建当前源码；安装后独立运行，不依赖保留源码目录。

## TypeScript 与版本资源

[构建脚本](../源码/构建.rs) 在 HOME 内的 Cargo `OUT_DIR` 严格编译扩展、真实 GJS 契约及基类桩。
只接受原生 ELF `tsc`，不使用脚本启动器；编译器变更触发重编译，生成前清除旧输出。
源码不提交 JS 副本。安装、契约测试和扩展 ZIP 引用同一份嵌入产物。

[扩展元数据生成器](../源码/扩展元数据.rs) 从 Cargo 项目版本派生 `version-name`
和兼容整数 `version = 主版 × 1000000 + 次版 × 1000 + 补丁`。
次版与补丁须小于 1000，结果为正的 32 位整数；非法版本使构建失败。
源码 `metadata.json` 只保存静态字段，安装与 ZIP 使用同一份生成字节，不手工维护第二个版号。
扩展网站发布时的整数序号由网站管理；本项目 GitHub 自分发使用上述编码。

## 包内容与来源校验

| 产物 | 内容 |
| --- | --- |
| 两个 Linux 原生包 | 独立二进制、项目许可、依赖原始许可、日志、发布说明及 `发行信息.json` |
| 源码包 | 当前已提交 Git 快照，由标准 `git archive` 生成 |
| GNOME 扩展 ZIP | 标准 `extension.js` 与生成的 `metadata.json` |
| SHA-256 清单 | 上述四个附件的摘要 |

`发行信息.json` 记录版本、提交、架构、二进制与扩展摘要。
`cargo 发布附件` 先验证两个架构包与当前提交、嵌入扩展一致，再生成源码、扩展和摘要清单。
归档验证检查全部条目的路径、类型、重复项和来源；不接受软链、硬链、设备或越界路径。

依赖许可从当前解析依赖收集，原始文本随包的 `LICENSES/` 分发；
仓库登记见 [第三方许可证](04-第三方许可证.md) 和 [依赖清单](06-Rust依赖许可证.tsv)。
日志由完整 Git 历史生成 `builddir/CHANGELOG.md` 与 `builddir/发布说明.md`，未提交修改不会进入日志。

## CI 与发布流程

- [持续集成](../.github/workflows/ci.yml) 对主线与 PR 执行双架构检查和原生打包。
- [发布工作流](../.github/workflows/release.yml) 校验标签与 Cargo 版本，完成相同检查，汇总两个架构包再公开附件。
- [原生准备器](../.github/流水线.rs) 通过 `rustc` 编译，只在 CI 内准备 HOME 源码副本、稳定工具链及必要依赖。
  它通过官方 `gh` 获取微软 TypeScript 最新正式架构资产，验证 SHA-256、归档路径和 ELF，再加入 PATH。
- [发布逻辑](../源码/库/流水线.rs) 判断远程主线归属并执行草稿上传和正式公开。

x86_64 和汇总使用 `ubuntu-latest`，ARM64 使用工作流声明的官方 ARM Ubuntu runner。
二进制使用对应 runner 的 glibc，不宣称静态链接或兼容所有旧系统。
项目及 CI 工具链不引入 Node/npm；官方 Actions 自身的内部运行时由平台管理。

## 版本与公开边界

应用版本唯一事实源为 `Cargo.toml`，同步提交 `Cargo.lock`，标签必须为 `v<版本>`。
只有标签提交属于远程 `主线` 历史才正式发布，其余为预发行且不设 Latest。
已公开的附件与标签不得覆盖或移动；只有草稿允许重试上传，修正公开版本需发布新版本。

普通文档提交不要求增加版本或重新发行。交付涉及二进制时，在已提交干净副本中构建并校验，
将本机验收、远程 CI、附件公开和宿主安装分别报告。推送与发行不会自动升级宿主安装。
历史验证及每次覆盖范围见 [历史索引](历史/README.md)。
