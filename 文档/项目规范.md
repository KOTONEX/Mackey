# Mackey 项目规范

本文集中维护 Mackey 的开发、验证与交付约定；AGENTS.md 与贡献指南引用本规范。
本项目是 GNOME Wayland 下的 macOS 风格按键映射工具，采用 Rust 与 TypeScript，许可证为 AGPL-3.0-or-later。

## 范围与工作区

- 用户当前意图、明确选择及会话内已有授权优先。初始化与规范化分别执行：新项目按用途
  建立最小可用结构；现有项目先读已有规范和实现，保留业务行为及公共接口。
- 开始前检查 Git 状态，区分本次任务、用户已有改动、暂存内容和未跟踪文件。
  不覆盖、清理、提交或分发无关内容；需要隔离时使用临时副本或独立工作树。
- 用代码、清单、Git 和实际命令核对事实。发现规范与实现矛盾时记录差异并修正相应来源，
  不以旧报告代替当前验证。
- 缺少会影响设计或授权的信息时尽早询问，同时推进不依赖答案的工作；普通实现细节
  自主决定，不把每一步可逆修改都变成确认流程。

## 语言与命名

- 自有文档、注释、界面提示和提交说明使用简体中文。自有 API、配置、命令、文件和目录
  在技术允许时采用简体中文；保留项目标识、语言关键字、文件扩展名及第三方原名。
- 外部平台、协议、格式和工具规定的字段、API 与标准文件名保持原文。
  例外须有规范或项目约定依据；遇到技术限制说明原因，不为翻译破坏互操作性。
- 使用目的明确的名称。重命名同步调用、配置、构建、测试、CI、打包和文档；公共接口的
  兼容或迁移策略由项目明确决定，不默认删掉已有兼容入口。

## 技术与依赖

- 根据用途、平台、部署方式和团队能力选择语言与技术，不预设某个项目的技术栈。
  划清运行、开发、构建与测试边界；跨语言桥接只在收益足以承担维护成本时引入。
- 通用解析、编码、摘要、容器和协议优先评估成熟第三方实现。核对维护情况、语义、
  许可证、平台支持与依赖成本，再决定替换；保留实现业务规则、事务和几何约束的必要代码。
- 替换自有实现时核对顺序、覆盖、空值、错误位置和边界行为，验证实际不变量。
  不为减少行数改变已有语义，也不把薄封装一律视为重复造轮子。
- 按生态维护依赖清单、锁文件和更新策略。清单没有某类依赖不等于工具无用：还须检查
  源码、构建、CI、外部 SDK、测试和发布过程的调用，再删除运行环境。
- 运行时依赖与开发工具依赖分别说明，避免把构建环境要求误写成最终用户安装要求。

## 工具链

- 本地开发、检查、构建及 CI 使用上游最新稳定版工具链，不固定编译器或运行环境的
  数字版本；beta、RC、nightly 和 dev 不代替稳定版。仅有稳定渠道配置不能证明已经更新。
- 准备阶段通过官方渠道核对实际版本，按当前管理器更新；需要变更全局环境时遵循
  任务授权。普通编译、测试与打包不联网查询最新版本，也不擅自升级全局环境。
- 最新稳定版不兼容时修复源码、类型或配置并验证；不以回退旧版本掩盖问题。
  如外部平台强制限制工具版本，记录具体限制与冲突，不能把旧版本验收称为最新稳定版验收。
- 依赖锁文件、语言版次、目标平台和输出协议不等同于工具链版本固定；这些约定仍需
  明确维护。验收及基准记录当次真实版本，不承诺不同工具链的产物逐字节一致。

## 项目结构与事实来源

- 按职责组织源码、测试、资产和文档；缓存、状态、配置与构建产物使用适合的存储位置。
  技术要求的标准目录保持原名，不为统一外观破坏工具约定。
- 文档按阅读目的组织：使用说明、开发流程、参考登记与历史记录。有内容时再分目录，
  小项目可合并文件。README 介绍用途、安装、基本使用和入口；AGENTS.md 保留稳定约束、
  事实位置及验证命令，不堆叠实现细节或迭代日志。
- 确定版本、关键配置和许可证范围的单一事实来源。其他清单从中派生或验证一致性，
  不手工维护多份互相独立的版本号。
- 标明源码与生成产物关系：如何再生成、哪些应跟踪、哪些只供构建。
  应随交付分发的产物与来源、许可、清单一起维护，不手工修补生成文件。

## 构建与验证

- 提供项目适用的统一检查入口，汇总必要格式、类型、静态分析、测试及产物校验；
  必须能实际运行。耗时集成、视觉或性能验证单独按改动选择，明确统一入口的覆盖范围。
- 检查缺工具、缺平台或缺显示环境时明确失败或报告未完成；不把跳过当成通过。
  实际工具警告如何处理由项目定义，结果不能用空测试或恒真断言充数。
- 测试关注行为和关键不变量：错误恢复、边界输入、配置作用域及交付内容。
  可逆的低影响文案、路径修订用现有检查和链接核验，不机械新增复述实现的测试。
- 涉及真实宿主、页面或系统集成时使用独立环境，不打断用户工作会话。
  模拟对象通过只证明所覆盖逻辑，磁盘写入成功不证明当前运行会话已加载。
- 检查与改动相称。已有必要检查通过后继续完成任务，不为增加数量反复运行无关测试。
  性能结论注明环境、版本、提交、样本方法和测量限制；旧样本不能代表当前实现。

## 文件、配置与事务

- 对实际需要多步骤一致性的操作准备输入，再写入；失败恢复原状态并报告恢复失败。
  跨文件、配置或外部服务的恢复能力按实现如实描述，不宣称不存在的全局原子性。
- 处理文件时明确路径、符号链接、权限和未跟踪内容的边界；交付只包含有意纳入的文件，
  不把私有设置、调试日志、凭据或临时产物带入包。
- 持久配置遵循目标平台约定。固定设置与持续同步行为分别说明；创建后台任务或服务前
  确认其必要性与用户授权，避免用常驻机制解决一次性任务。

## 许可证与第三方来源

- 新项目优先采用**强著佐权（strong copyleft）**，不默认改为宽松许可或弱 copyleft。
  可按项目用途评估 `GPL-3.0-or-later` 或 `AGPL-3.0-or-later`；具体选择、版本和范围
  写入项目规范。用户已有明确选择时采用其选择，不擅自增加双重授权或许可例外。
- 许可选型参考 [GNU 选型说明](https://www.gnu.org/licenses/license-recommendations.html)，
  正文使用对应官方完整许可，不用简短说明代替许可全文。
- 现有项目保留既有许可；规范化不自动重新许可。变更授权范围须有权利依据及明确授权。
  第三方及其衍生部分保留原许可，不因复制、格式转换或局部自有修改获得额外授权。
- 区分代码、资产、字体、数据及文档；按需要登记来源、版本、许可、署名和分发边界。
  引入或替换依赖前核对兼容性；存在具体疑点时查原文，不能凭偏好断言兼容。

## 提交、推送与发布

- 尊重会话内已获授权：提交、推送、标签、Release、市场发布和部署按任务分别判断，
  不从一个动作推断另一个动作，也不重复询问已经明确授权的步骤。
- 提交按实际路径暂存并核对差异，排除用户已有与任务无关的内容。说明最终改动和验证，
  可采用简体中文类型前缀：`新增:`、`修复:`、`文档:`、`测试:`、`重构:`、`杂务:`。
- 版本变化根据项目的对外兼容和交付规则决定，不因出现提交就升级。
  标签、发布说明及包清单相互一致；不移动已经公开的版本标签。
- 需要交付验收时从干净副本构建并核对内容、版本、许可和私有文件排除。
  构建依赖 Git 日志或标签时获取完整历史；同一工具链下验证所要求的确定性。
  本机安装、推送、远端发布和部署各自单独记录，不强制每个项目每次提交都安装。
- CI 复用缓存或产物时核对来源、提交、平台和完整性；找不到可用缓存可正常构建，
  校验错误不能悄悄忽略。发布只使用经过必要验证的交付物。
- 已公开产物保持可核验；重试的幂等边界、超时和停止条件按实际服务定义。
  缺少凭据、上传失败或发布步骤跳过时，准确报告各目标状态，不能统称发布成功。

## 文档与验收报告

- 当前说明记录当前行为，候选计划标明未实施，历史记录标明版本和日期。
  路径移动同步 Markdown、图片和锚点；规则集中维护，其余入口引用。
- 改动结束报告范围、执行的检查、产物及已完成外部动作。明确区分准备、已修改、

- 规范只有在命令、文件、CI 与文档相互一致时才算落实。初始化至少形成可验证的最小
  功能或构建链；纯规范文档任务则交付可适配规则，不声称已完成业务实现。

## Mackey 业务与运行边界

- `配置/行为清单.json` 是映射、归属、迁移和吞键例外的唯一事实源；`文档/03-行为清单.md` 由它生成，不手工修补。
- 不做全局 Ctrl/Super 交换；微软布局仅交换 Alt/Super 的物理位置。应用分流必须保留终端与 IDE 的 Ctrl+C/SIGINT；吞控制组合使用独立 keymap，并以 `application.not` 排除终端配置档及例外应用。
- GNOME 冲突只迁移实际冲突的键，先备份再设置；迁移失败回滚本次原值，恢复失败保留备份并报告。还原与卸载先完整验证备份，不能把无效数据变成空绑定。
- 焦点来源或 socket 未就绪时拒绝启动引擎；来源查询失败后清除缓存并退出焦点桥，引擎用 `BindsTo` 和 `After` 绑定焦点桥，不使用无限过期的焦点。
- Mackey、安装卸载及本地测试拒绝 root，不调用 sudo，不写系统配置或安装 udev 规则。所有持久写入和测试临时目录限制在 HOME，逐段解析软链与 `..`；路径检查入口为 `源码/库/路径.rs`。
- 唯一 IPC 例外是 `/run/user/$UID/mackey-focus.sock`（0600），不创建系统目录；自定义 socket 必须在 HOME 下。虚拟键盘测试显式访问 `/dev/uinput`，不安装规则。
- 安装保留用户字段、补齐缺字段、备份损坏 JSON；默认卸载清除配置，`--保留配置` 显式保留。不存在的服务单元跳过禁用，重复卸载应成功。
- 旧自有命令、配置键与布局值不增加兼容读取或自动转换；拒绝后提示旧版卸载、还原并清除配置，再安装新版。布局值为 `苹果`、`微软`、`自动`；自动生成实时识别，不改写输入配置。初始化会把自动保存为当时识别值，热插拔不会持续切换。
- 支持 GNOME Wayland；X11 不受支持的提示仅留在文档，不新增会话类型检测或运行时拦截。保留 GNOME 桌面预检。

## 实现、工具与文件例外

- 主程序、配置生成、焦点桥、下载、安装卸载、测试编排与归档使用 Rust。GNOME 扩展、真实 GJS 契约与基类桩以 TypeScript 维护，最小外部类型声明见 `类型声明/GJS环境.d.ts`。
- 扩展的 `version-name` 在构建时由 Cargo 项目版本生成，安装和 ZIP 共用嵌入元数据；源码 metadata.json 只保存静态字段。遵循 GNOME 格式（1 至 16 个字母、数字、空格或点），不手工设置扩展网站管理的整数 `version`。
- 原生 ELF `tsc` 严格编译资源，Cargo OUT_DIR 必须在 HOME；不提交 JS 副本，缺编译器或类型错误即失败。工具升级触发重编译，重新生成前清理旧输出。安装、契约与 ZIP 引用嵌入产物，运行发行二进制无需编译器。
- 本地、CI 和发行程序均不引入 Node/npm。CI 用官方 `gh` 获取微软 TypeScript 最新正式发行的 Linux 架构包，校验发行资产 SHA-256，记录编译器版本；GitHub 官方 Actions 自身运行时由平台管理。
- Rust 使用最新 `stable`；Edition 显式声明当前稳定值，新稳定 Edition 发布后迁移验收更新，不设永久固定版本。准备阶段核实本机工具与官方稳定版；普通构建不联网更新工具。
- 系统开发工具使用 runner 稳定仓库可用版本；Actions 使用官方最新稳定主版本标签。临时 CI runner 可安装系统开发依赖，业务与测试仍为普通用户并放在 HOME。
- x86_64 和发布汇总使用 `ubuntu-latest`；ARM64 使用最新可用官方 ARM Ubuntu 标签，目前为 `ubuntu-26.04-arm`，平台未提供 `ubuntu-latest-arm`。
- 外部协议与工具约定的 Cargo、Git、systemd、XDG、GJS、GNOME、xremap 标识、文件名、第三方许可证及 `mackey` 项目前缀保持原文。部署文件 `config.json`、`xremap.json`、`relocations.json`、`backup/gsettings.json` 与 `bin/mackey` 保留既定路径；完整说明见 [中文接口迁移](07-中文接口迁移.md)。除此之外，自有接口使用中文，不增加英文别名。

## 实际验收与发行

- 统一入口 `cargo 检查` 包含格式、Clippy（警告视为失败）、Rust/严格 TypeScript 类型、三个薄壳的 ShellCheck、JSON、115 映射完整差分、Rust 单元及隔离集成测试、真实 GJS/D-Bus 契约。
- `cargo 测试` 跑差分、Rust 与真实 GJS；`cargo 测试 --端到端` 额外访问设备，先确认没有全局引擎及焦点窗口可接受透传键。不得擅停用户服务；测试只清理本次进程组与设备，未运行要说明。
- `cargo 格式化` 格式化；`cargo 运行 <子命令>` 和三个薄启动壳均通过 Cargo 构建当前源码，不绕过构建使用陈旧二进制。离线生成文档使用临时输出目录，避免覆盖运行配置。
- `cargo 打包` 编译 rustc 宿主，读取 Cargo 产物目录，生成原生包并解压运行独立二进制；`cargo 发布附件` 校验双架构包并组装源码、扩展和 SHA-256。原生包附版本、提交、架构及二进制/扩展摘要，汇总要求两包与当前提交、嵌入扩展相同；源码由标准 `git archive` 产生。
- 应用版本唯一事实源为 Cargo.toml，Cargo.lock 纳入 Git 并使用 `--locked`。日志由完整 Git 历史生成 `builddir/CHANGELOG.md` 和 `builddir/发布说明.md`，不手工维护，未提交改动不会进入日志。
- 只有标签提交属于远程 主线 历史才发布正式版；其余一律预发行且不是 Latest。已公开 Release 不覆盖附件或重写标签；只允许草稿重试上传，修正发布新版本。
- 本会话已授权正常提交并直接推送 主线、自主标签；不再保留 rust 分支。这是当前授权边界，不把一般规范当作新授权。宿主安装属于单独动作，不能从审查或发行推断。
