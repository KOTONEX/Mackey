# Mackey 2.4.0 端到端与发行验收

> 本文中的 `main` 是当时的分支名称，现已更名为 `主线`；历史测试记录保留原称。

## 结论

2026-10-09 在真实 GNOME Wayland 会话中运行 `cargo 测试 --端到端`，Cargo.toml 与 Cargo.lock 已为 2.4.0，包含 [完整项目审查](11-完整项目审查.md) 的全部修复。五项虚拟键盘用例全部通过，应用正反例使用真实 D-Bus 焦点来源 `app.zen_browser.zen`。

本次不是复用历史测试：先保存本机运行状态并停止现有全局引擎和焦点桥，实际注入设备事件，随后在 finally 中恢复原有服务；无论测试成功或失败都执行恢复。

注入器采用真实 Linux uinput，xremap 只抓取 `mackey-test-*` 设备。输入节点可读、引擎保持打开输入 FD 且输出设备创建后才发送事件。命中以 Rust 动作探针创建文件验证，排除项必须没有文件；测试 RAII 清理本次进程组与虚拟设备。

## 离线检查与宿主恢复

同次测试执行 42 项 Rust 测试（19 库、5 CLI、16 隔离安装卸载、2 参数/ABI）、13 项真实 GJS/D-Bus 断言及 115 条映射差分，全部通过。发行前另执行 `cargo 检查` 验证格式、Clippy、严格类型、ShellCheck、JSON 和上述离线验收。

恢复后逐项对照测试前快照：

- 焦点桥和全局引擎均为 active、enabled，与测试前相同。
- config.json、xremap.json、relocations.json、backup/gsettings.json 的 SHA-256 全部相同。
- 备份涉及的 21 项实际 GNOME 键位字符串全部相同。
- `mackey-test-*` 残留设备为 0；已安装程序体检显示 0 项待处理。

宿主恢复的是原有 Mackey 2.3.1 服务，本次用户授权测试与发布，不自动把 2.4.0 安装到宿主。版本号变化不会使已运行进程自动更新。

## 2.4.0 集成与交付

本版本包含完整审查修复、统一项目规范以及这次真实设备报告。保留此前正常提交历史，版本和报告作为新的交付提交；`main` 按用户明确授权快进到这一完整版本，不覆盖旧标签。

发行使用已提交的干净副本打包验证，并由 main 与 v2.4.0 对应工作流执行双架构离线检查、包验证、提交/二进制/嵌入扩展同源校验和 SHA-256 附件清单。只有成功通过验证才公开 [2.4.0 正式发行](https://github.com/KOTONEX/Mackey/releases/tag/v2.4.0)；具体执行状态见仓库 Actions，不把本机设备测试当成 ARM 设备验证。

## 范围

真实设备测试验证最小探针映射的分流与排除链路，没有逐条按下 115 组业务键；kitty/code 为固定身份，没有实际打开这两个应用。真实扩展由隔离 GJS/D-Bus 契约另行覆盖；本次没有故障注入真实用户总线或测量延迟、长期稳定性。ARM64 仅运行原生离线 CI 和打包。

历史首次安装、问题诊断与 2.3.1 恢复过程见 [历史本机报告](10-本机端到端测试报告.md)。
